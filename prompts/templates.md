# AI 提示词模板

以下模板为本项目实际使用的提示词结构，可按场景替换尖括号内容。

## 1. 项目初始化

```
在 <目录> 从零构建并交付一个可直接运行、可通过 GitHub 部署的 Java 应用（业务：<场景>）。
硬性门槛：
1) 应用可启动，核心链路可跑通：<链路>
2) 前端可访问，不依赖外网 CDN
3) 仓库自带 Dockerfile、docker-compose.yml、GitHub Actions（构建测试/镜像推送/SSH 部署）
4) 交付源码、配置、部署文档、演示文档、AI 使用说明
技术规范：Java 17 + Spring Boot 3.2.x + Maven Wrapper；JPA + Flyway；默认 H2 文件库；
MySQL/PG 可选 profile；JWT + BCrypt + RBAC；统一响应体、全局异常、参数校验、分页、OpenAPI、Actuator。
要求 mvn test 全绿、实际启动、脚本走完整链路并记录证据到 docs/verification.md。
```

## 2. 业务规则

```
实现以下规则，并为每条给出可验证的错误码与边界条件：
- 状态机：<状态列表与合法流转>
- 计分：<公式、最低分、奖励规则>
- 限流：<窗口、次数、冷却>
- 排行榜：<排序、同分规则、聚合规则>
- 权限：<角色与接口矩阵>
非法操作必须返回业务错误码，不得静默成功；关键逻辑加注释。
```

## 3. 双模式与双榜

```
同一业务需要两种模式：<限时模式> 与 <长期模式>，分别独立统计，不得串分。
排行榜需要 <个人榜> 与 <团队榜> 可切换；团队榜聚合规则为 <规则>，需写入文档与实现。
前端提供模式入口与榜单切换；管理端可创建两种模式并配置归属。
演示脚本中两种模式各走一遍。
```

## 4. 测试补齐

```
为以下链路编写单元测试与 MockMvc 集成测试：<链路>。
覆盖：成功、参数校验失败、未认证、越权、重复操作、限流、状态非法。
断言统一响应 code 与关键字段；测试 profile 使用独立数据库与临时上传目录。
运行 mvnw test 并修复至全绿，输出统计。
```

## 5. 部署与文档

```
按"推仓库 → 配 Secrets → 服务器执行一条命令"写 DEPLOY.md。
必须包含：公开/私有仓库差异、包可见性、端口与防火墙、SSH 密钥、健康检查、
数据卷与重启自恢复、常见故障排查、备份与回滚。
README 给出快速开始、演示账号、默认端口、接口一览、部署三步。
```

## 6. 失败排查

```
命令/测试失败日志如下：<日志>
请定位根因（不要猜测），给出最小修复，说明影响范围，并重新运行验证命令。
若环境缺失（JDK/Maven/Docker），先探测已有版本，优先便携安装；失败则记录原因并给替代方案。
```
